1週間の流れ

  1. 金曜 朝5時

    収集

    9つの技術分野（AI・ロボット・特殊鋼・研削・切削・放電・治具・測定・金型）の業界紙やメーカー発表から、候補記事を集めます。記事は元のWebページの原文を直接読み込みます。

  2. 金曜 朝5時

    執筆

    AIエージェント（Claude Code の自動実行）が、記事の採否を判断し、AI要約と「現場の視点」コメントを書き、記事の写真を選び、一覧ページ用のアイコンを作ります。「現場の視点」は、金属加工に50年携わってきた会社の理念や感覚を、会社のホームページの情報をもとに用意し、AIにあらかじめ覚えさせてから書かせています（AI秘書の講習で学んだ「自分トリセツ」の考え方に沿って、あとから整備しました）。

  3. 金曜 朝5時

    組み立て

    カテゴリ別のWebページ（HTML）と、掲示・配布用のPDFにレイアウトします。

  4. 金曜 朝5時

    自動検証

    ブラウザ自動操作（Playwright）で、ページのエラー・画像の読み込み切れ・各記事の詳細（要約・要点・「現場の視点」・元記事リンク）の抜け・PDFのページまたぎを点検します。合格した号だけが、次へ進みます。出典の欠落などの警告は、点検メモに残します。

  5. 金曜 昼13時

    自動公開

    合格した号を、Git（GitHub）へ自動で公開します。公開されたページが、そのままWebサイトになります（GitHub Pages）。

  6. 月曜 朝8時

    自動配信

    社内チャットツールに、新しい号の案内を自動で配信します（GitHub Actions）。

  7. いつでも

    止める

    気になる号があれば、「今週は止める」ボタン1つで、その週を止められます。未公開の号は公開ごと止め、公開済みの号は、月曜の配信だけを取り消せます。

品質を守るルール

  • 出典は、一次情報・ニュース記事に限ります。ランキングやSEO記事、カタログ、個人ブログ、販促、AI生成の記事は使いません。
  • 出典に無い数値・型番・社名・日付は書きません。数値は、元のWebページの原文を直接読み、その文字列があることを確かめてから書きます。
  • 断定や推測は書きません。全ページに出典元と免責事項を載せます。
  • 本数を埋めるために、過去号のネタを焼き直しません。新着が少ない週は、品質を優先して本数を減らします。
  • 検証に合格しなかった号は、公開されません。

止まらないための工夫

  • 人の事前承認は無く、止めたい週だけ止める方式にして、担当者が不在でも止まらないようにしています。
  • 各工程に予備の実行時刻を用意し、見張り役が、金曜12時・15時半と月曜9時半に、下書き・公開・配信の記録を点検します。
  • データベースは使わず、ファイル（JSON・HTML・PDF）で管理します。号ごとのフォルダに、候補記事・検証結果・点検メモ・公開済みの記録を残します。

公開の方法

公開は、Git（GitHub）への自動公開（GitHub Pages）で行います。この展示ページも、同じ仕組みで置いています。

# 週刊テックナレッジ 編集エージェント（設計書）

> 実際の運用で動いている仕組みの、全体像・処理の流れ・守るルールを書いたものです（社内の名前や記事は伏せています）。

## このエージェントが担う仕事
金属加工の現場の社員や新人が、**流し読みなら5分でざっくり把握できる**技術ダイジェストを、毎週欠かさず届ける。
人が手作業でやると 1号あたり約7時間（話題探しから公開まで。通常業務の合間では1週間がかり）かかる仕事を自動で回し、人は公開された号の抜けと、社内チャットへの投稿を確認する約5分だけにする（時間は作者の見積もりで、実測ではない）。

## 全体像（1週間の流れ）
| いつ | 何をするか | 担当 |
|---|---|---|
| 金曜 朝5時 | ①記事の収集 → ②AIエージェントが判断・執筆（採否・要約・「現場の視点」・写真・一覧ページのアイコン）→ ③HTMLの組み立て → ④自動検証とPDF → ⑤点検メモの作成 | スクリプト＋AIエージェント（Claude Code の自動実行） |
| 金曜 昼13時 | 検証に**合格した号だけ**を、Git（GitHub）へ自動で公開する（公開されたページが、そのままWebサイトになる）。月曜の配信文も、このとき予約する | 自動 |
| 月曜 朝8時 | 社内チャットツールに、新しい号の案内を自動で配信する（GitHub Actions） | 自動 |
| 金曜12時・15時半、月曜9時半 | 見張り役が、下書き・公開・配信の記録を点検する | 自動 |
| いつでも | 「今週は止める」ボタン1つで、その週を止められる（未公開の号は公開ごと止め、公開済みの号は月曜の配信だけを取り消す。取り消しの取り消しもできる） | 人（気になる号があったときだけ） |

- 各工程には、予備の実行時刻を用意している（起動の遅れや失敗に備える）。
- 人の事前承認は無い。止めたい週だけ止める「オプトアウト方式」にして、担当者が不在でも止まらないようにした。
- データベースは使わず、ファイル（JSON・HTML・PDF）で管理する。号ごとのフォルダに、候補記事・検証結果・点検メモ・公開済みの記録を残す。

## 入力
- **9つの技術分野**：AI・スマートファクトリー／ロボット・現場自動化／金属素材・特殊鋼／研削加工／切削加工／切断・放電加工／ワーク固定・治具／測定・幾何公差管理／金型・精密プレート
- 各分野の業界紙・メーカー・研究機関の発表。収集の期間は、発行日の45日前まで。
- 過去号で使った記事の出典URLの台帳（過去号の記事は、別のURLでも、同じ話題なら使わない）。

## 処理フロー
**① 収集（スクリプト）**：各分野の候補記事を集め、元のWebページの**原文（生のHTML）を直接読み込んで**本文テキストにする（要約を介さない。数値がぶれるのを防ぐため）。期間外の記事と、使用済みの記事は、印を付ける。

**② 判断・執筆（AIエージェント）**
1. **採否の判断**：取得した本文を**実際に読んで**、採用するかを決める。出典は、一次情報（発表）とニュース記事に限る。ランキング、「〇〇とは」型のSEO記事、製品カタログの恒久ページ、個人ブログ、市場調査の販促、AI生成の記事は採らない。
2. **構成の決め方**：1カテゴリは最大2本、「🔰 基礎から学ぶ」は1号に最大2本。本数の目安は6〜10本だが、**届かなくても品質を優先する**（本数を埋めるために、過去号のネタを焼き直すことはしない）。直近8号で扱った話題は、URLが違っても採らない。
3. **要約**：リード1〜2文（60〜100字）＋箇条書き3〜5点（1行40〜60字）。**書く数値・型番・社名・日付は、取得した本文にその文字列があることを確かめてから書く**。確かめられない数値は載せず、定性的な表現にする。断定や推測は書かない。
4. **「現場の視点」コメント**：1文目で「これは、〔誰〕が〔何を〕した、という話です」と記事の主題を言い直し、そのあと、**自分たちの加工現場にどう関係するか**を、共感 → 現場での効き目 → 謙虚な好奇心、の流れで書く（3〜4文・150〜200字）。断定・保証・評論家口調・問いかけ調は使わない。
   - この視点は、金属加工に50年携わってきた会社の理念や感覚を、会社のホームページの情報をもとに用意し、エージェントにあらかじめ覚えさせてから書かせている。エージェントには、「記事を選ぶ・要約する・コメントを書く、すべての工程で、会社の技術者が本当に言いそうか、を自問する」ことも求めている（AI秘書の講習で学んだ「自分トリセツ」の考え方に沿って、あとから整備した）。
5. **写真の選定**：記事1本につき写真1枚。過去号の写真の再利用、または公開の写真サービスから探し、**画像を実際に目で確かめて**（無関係な画像・不正確な画像を除く）、隣り合う号と重ならないようにし、クレジットを残す。
6. **一覧ページ用の素材**：号カードのトピック文と、線画のアイコンを新しく描く。過去号とシルエットが似ていないかを、並べた画像で**自分で確かめる**。配信文用の「号のテーマ」と「要点3つ」も決める。

**③ 組み立て（スクリプト）**：カテゴリ別のWebページ（HTML）と、掲示・配布用のPDFにレイアウトする。全ページに、出典元と免責事項を載せる。

**④ 自動検証（ブラウザ自動操作 Playwright）**：ページのエラー、画像の読み込み切れ、IDの重複、各記事の詳細（要約・要点3つ以上・「現場の視点」・元記事リンクの形式）の抜け、PDFのページまたぎ、を点検する。**合格（ok）した号だけ**が次へ進む。

**⑤ 点検メモ**：スレート一覧・出典・日付・警告（出典の欠落、期間外の日付、写真の重複など）を、点検メモに書き出す。公開後の点検に使う。

**⑥ 公開・配信**：合格した号だけを、一覧への追加・前号への次号リンク・次号の番号の更新まで行って、Git（GitHub）へ公開する。配信は、金曜に文面を予約し、月曜の朝にGitHub Actionsが投稿する（投稿済みの号は、二重に投稿しない）。

**⑦ 停止**：「今週は止める」があれば、その週は、公開も配信もしない。

## 守るルール
- 出典は、一次情報・ニュース記事に限る。弱い出典は使わない。
- 出典に無いことは、一切書かない（人の目が入らない前提のため）。迷ったら、本数を埋めるより、基準を満たすことを優先する。
- 数値は、元のWebページを直接読んで確かめる。
- 断定や推測は書かない。記事中のコメントは個人の見解であり、会社の公式見解ではない、と明記する。加工条件は参考値であり、社内の作業標準を優先する、と配信の文に必ず添える。
- 検証に合格しない号は、公開しない。
- エージェント自身は、既存の号の書き換え・commit・push・デザインの変更をしない（公開は、別の仕組みが行う）。

## 出力
- 各号のWebページ（HTML）と、PDF版
- 検証の結果（合格・不合格と、その理由）と、点検メモ
- 一覧ページの号カード用の素材、社内チャットツールへの案内文

## 運用で分かったこと（作り直しの記録）
- 第1〜5号を発行した段階で自分で品質を監査したところ、出典の約83%がニュースではない弱い情報源で、AIによる事実誤認（捏造）も2件見つかった。そこで、①一次情報・ニュース記事に限る出典の基準、②元のWebページを直接読む方式、③断定・推測の禁止ルール、を定め、過去号もすべて作り直した。
- 社内チャットツールへの自動配信は、定時の起動が遅れたり飛んだりする週があり、予備の時刻と見張り役を足して、安定して届くよう調整を続けている。

## 展示用の公開ページについて
実際の運用（社内向け・非公開）の記事・企業名は出せないため、展示用のページは、**本番と同じプログラムとデザインで、架空の記事を組んだ全14号のサンプル**である。

2026年8月14日の第1号から、毎週発行を続けています。最初の5号を自分で監査したところ、出典の多くがニュースではない弱い情報源で、AIの事実誤認も見つかりました。そこで出典の基準を厳しくし、過去の号をすべて作り直しました。

社内チャットツールへの自動配信は、定時の起動が遅れたり飛んだりする週があり、安定して届くよう調整を進めています。
